ShuNukes — заметки по коду (пересборка из ShuNukes_old, 2026-09-23)
=====================================================================

Типы торпед (технический тип -> игровое название -> где продаётся)
  NukeTorpedo          -> Ядерная торпеда          -> Доминион (игрок-пират, звание >= Головорез)
  DirtyNukeTorpedo     -> Термоядерная торпеда     -> ВБ (звание >= Истребитель)
  CombinedNukeTorpedo  -> Гибридная торпеда        -> ВБ, ГТУ > 6
  EMNukeTorpedo        -> Электромагнитная торпеда -> ВБ, ГТУ > 4
  NeutronNukeTorpedo   -> Нейтронная торпеда       -> ВБ, ГТУ > 5
  ПБ ничего не продаёт: только первый разговор-наводка (ветка «нет звания»), других текстов у ПБ нет.
  Годовой лимит = (звание - 2) * 4, общий на базу: на ВБ считается по DirtyNukeTorpedo, на Доминионе по NukeTorpedo.
  Обнуление 1 января.

Мёртвые / условно мёртвые ветки (оставлены намеренно)
  1. Инфошка ShuNukes_NPCNuclearMissiles (армадная) нигде не создаётся:
     DistributeNukeMissiles в обеих ветках if(EvoArmadaInit) вешает ShuNukes_NPCNuclearMissilesNoArmada,
     ShuWarriors её только ищет (с запасным поиском NoArmada). Её акткод не выполняется. Не трогаем.
  2. Вооружение станций (диалоги StationNukes / StationNukesBuy, операции #77 #78 #99 #100)
     включено только без Expansion\ExpHullsBases (при нём эту роль берёт ExpHullsBases).
  3. ПБ — только разговор, продажи нет. Так задумано.
  4. ShuNukes_TargetEMNuke, OnActCode:
     - ветки else с Dist(bomb, ...) не выполняются: boom_ship (корабль, в который попала торпеда) всегда задан;
     - блок с t_OnItemPickUp у Rattor не выполняется: акткод получает только t_OnStep и t_OnTakingDamageMi;
     - у домиков подтипа 7 выполняется только первая ветка !ScriptItemActionType(t_OnStep, 11):
       в ветке урона событие никогда не t_OnStep.
     Оставлены как есть.
  5. Ветки t_OnEnteringForm в NPC-инфошках не срабатывают (NPC не открывают формы). Безвредно, оставлено.

Прицеливание (2026-09-24)
  Игрок может навести ядерку на корабль или станцию (кроме себя) в пределах дальности,
  если прочность корпуса цели HullHP >= 500. Проверка одна для всех (EvoArmada/EvoDreadnought не учитываются).
  Выбор целей NPC (их эвристики, кого стоит бомбить) не менялся.

Залп
  Игрок ставит через диалог ровно одну пусковую, залп = 1 торпеда.
  Несколько шахт у игрока бывает только при пересадке на флагман через ShuWarriors (корпус флагмана с его шахтами);
  тогда число торпед в залпе выбирается в NumberBox. Пуск ограничен числом торпед в трюме.

Движковые особенности, из-за которых были баги
  - Тип выражения = тип левого операнда: CT() возвращает строку, CT('150') + 165 = '150165'.
    Все параметры торпед читаются через int(CT(...)), в g_NukeParams хранятся числа.
  - ItemSize(item, value) меняет размер только если value не строка (иначе работает как геттер) —
    отсюда был нулевой вес утяжелителя.
  - IdToItem не видит корабли в гиперпространстве (Galaxy.ShipsInTransit) — утяжелитель «пропадал».
    Теперь его ищет по трюму функция скрипта SyncNukeWeight (удаляет дубли, ставит вес = шахты * NukeShaftWeight).
  - t_OnTakingDamageMi: ScriptItemActObject1() — сама ракета, ScriptItemActObject2() = 0.
  - Global:true переменные скрипта (g_NukeParams) видны из акткода и Main, но акткод и Main читают
    параметры напрямую из Lang через int(CT(...)).
  - Строки акткода в Lang склеиваются без переносов: // в акткоде закомментирует весь остальной код.

Сборка
  1. RScript 4.15: RScript.exe --cli -b Mod_ShuNukes.rson Mod_ShuNukes.scr Mod_ShuNukes.txt --full
     (ExportLangTxt/ExportLangDat включены: строки скрипта 0/1/2 вливаются в Lang.txt).
  2. ExportLangDat вливает строки в СТАРЫЙ Lang.dat, а не собирает его из Lang.txt, поэтому после компиляции:
     BlockParEditor.exe --cli --convert CFG\Rus\Lang.txt   (и так же Eng\Lang.txt, Main.txt)
  3. Lang.txt / Main.txt хранятся в UTF-16LE с BOM.
